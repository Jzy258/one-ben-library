* 未来方向：
	* 表达能力：动态形状 + 前 / 后处理
		* 运行时才知道 NLP 输入形状
		* 前 / 后处理被 Python 拖慢
		* 编译器需要支持完整控制流
	* 调优进化：高级自动调优
		* 逐算子调优 ≠ 全局最优
			* 跨算子可联调
		* 执行时间不再是唯一目标
			* 内存、能耗
		* ML 可以介入更多阶段
	* 数学深化：多面体模型
		* 多面体 + 自动调优互补
			* 自动调度缩小搜索空间
			* 复用配置降低 JIT 开销
		* 稀疏张量使下标非仿射，阻碍多面体
	* 执行形态：子图划分
		* 将图切成子图分别执行
		* 继承图库：
			* nGraph + DNNL
		* 异构并行：
			* ARM CPU / Mali GPU / DSP / NPU
	* 数值与生态：量化 + 统一优化
		* 量化：编译期导出更高效的量化策略
			* Relay 量化重写
			* dialect 实现新算子
		* 统一优化：
			* MLIR 用 dialect 使各编译器互相复用
	* 新范式与新边界：可微编程 + 隐私保护 + 训练支持
		* 可微编程 = 程序整体可微
			* 语言语义难
		* 隐私 = 边缘 - 云中间结果泄露
			* 编译器可自动定位噪声插入层
		* 训练支持 = 当前全偏推理，扩展可开梯度算子优化 / 高阶自动微分
* DL 编译器演进：
	* MLIR 成为统一基础设施的事实标准
		* TF、PyTorch、IREE 全部建立在 MLIR 上
	* 编译器进入框架成为主流
		* 用户无需手动使用编译器，框架默认走编译栈
	* Triton 流行
		* GPU 上类 Halide 的 DSL（领域特定语言）
	* LLM 时代编译器转向推理优化
		* KV cache、张量并行、量化、TensorRT-LLM 等
	* JAX 验证可微编程
		* 将 autodiff + XLA 编译一体化
	* 边缘子图划分 / 异构成为标配
		* ONNX Runtime 的做法
