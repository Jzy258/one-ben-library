* 自动调优：
	* 由机器自动搜索参数调优
	* 关键组件：
		* 参数化、成本模型、搜索技术、加速
* 参数化（Parameterization）：
	* **包括**：
		* 数据参数（**如**：输入形状）、目标参数（**如**：GPU 的共享内存大小 ）
		* 调度方案及参数
	* TVM：
		* 同时考虑预定义 + 用户自定义调度与参数、
	* TC/XLA：
		* 只参数化与性能强相关、后期能以低成本改变的优化
* 成本模型（Cost Model）：
	* 黑盒模型：
		* 只测试最终执行时间，不分析任务特征
		* **优点**：
			* 便于搭建
		* **缺点**：
			* 开销大，解不优
		* 采用者：
			* TC
	* 基于 ML 的模型：
		* 用机器学习统计预测性能，随探索不断更新
		* **优点**：
			* 精度更高
		* 采用者：
			* TVM、XLA
	* 预定义模型：
		* 按编译任务特征构建最适模型
		* **优点**：
			* 运行时开销小
		* **缺点**：
			* 新 DL 模型、硬件需要重建预定义模型
* 搜索技术（Searching Technique）：
	* 确定初始化 + 搜索空间：
		* 可以随机或使用已知配置
		* TVM：
			* 使用领域知识指定搜索空间，按计算描述自动提取
	* 遗传算法（GA）：
		* 参数 = 基因
		* 配置 = 个体
		* 按适应度交叉 / 变异 / 选择迭代演化
		* 采用者：
			* TC
	* 模拟退火（SA）：
		* 以递减概率接受更差解
		* 跳出局部最优，逼近全局最优
		* 采用者：
			* TVM
	* 强化学习（RL）：
		* 引入奖励机制，学习使奖励最大的策略
		* 采用者：
			* Chameleon
* 加速（Acceleration）：
	* 并行化：
		* TC：
			* 使用多线程 + 多 GPU
			* 候选入队 -> 多 CPU 线程编译 -> GPU 并行评估
		* TVM：
			* 交叉编译 + RPC（Remote Procedure Call，远程过程调用）
				* 在算力强大的主机上编译
				* 在资源受限的边缘设备上运行
	* 配置复用：
		* TC：
			* 编译缓存
		* TVM：
			* 日志文件存所有算子的最优配置
			* 对 Halide IR 中的每个算子分别自动调优
* 优化内核库：
	* **如**：
		* DNNL（MKL-DNN）、cuDNN、MIOpen
	* TVM、nGraph、TC：
		* 能在代码生成时生成对优化库的函数调用
	* **局限**：
		* 需要将数据布局与融合风格转换为优化库接口指定类型
			* 可能破坏最优控制流
		* 优化库为黑盒不可控，无法跨算子优化
	* 优化对象：
		* 计算密集：
			* conv/GEMM/RNN
		* 内存带宽受限：
			* BN/pool/shuffle
