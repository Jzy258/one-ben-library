# 05 （Java 5）泛型

* 泛型
	* 泛型（参数化类型）：
	* 在定义类、接口时通过一个标识符表示某个属性的类型、某个方法的返回值或参数类型，参数类型在具体使用时确定，使用前对类型进行检查
	* 可以使同一套代码适配多种数据类型，无需重复编写逻辑，也无需增写父类并频繁类型转换，提高了代码的复用性
	* 提高代码的可读性，更容易分辨类（或接口）所关联的类型
	* （Java 7）钻石表达式：实例化带泛型的对象时，构造方法中 `<>` 中的数据类型可以省略：
      ```java
      类名<类型> 变量名 = new 类名<>(参数列表);
      ```
	* 使用泛型后，**编译器**会对数据类型进行检查，避免运行时出现类型错误（`ClassCastException`）的问题，提高了安全性
* 泛型的使用
	* 泛型类：具有至少一个类型变量的类
	* 定义类时在类名后加 `<泛型标识>`
	* 定义多个类型变量时，泛型标识之间用 `,` 隔开
      ```java
      class 类名 <泛型标识> {
  	private 泛型标识 变量名;
  	...
      }
      ```
	* 静态方法的返回值类型不能使用泛型
		* 静态方法在类加载时已经确定数据类型，而在泛型需要手动指定
	* 泛型类可以看成普通类的工厂，可以生产出各种带有配套数据类型的实现类
	* 泛型方法：
      ```java
      修饰符 <泛型标识> 返回值类型 方法名(泛型标识 变量名) {
  	...
      }
      ```
	* 在返回值类型前定义了 `<泛型标识>` 后，在该方法中就可以使用该泛型
	* 返回值类型和参数类型都可以使用已经定义的泛型
	* 泛型接口：
      ```java
      interface 接口名<泛型> {}
      ```
	* 接口中的属性默认被 `static` 修饰，不能使用泛型
	* 实现泛型接口：
		* 确定类型：
          ```java
      	class 类名 implements 接口名<类型> {}
          ```
		* 不确定类型
          ```java
      	class 类名<泛型> implements 接口名<泛型> {}
          ```
	* 常用泛型标识：
	* `T`：Type（类型），表示任意类型
	* `E`：Element（元素），表示集合的元素类型
	* `K`：Key（键），一般与 `V` 连用
	* `V`：Value（值），一般与 `K` 连用
	* `S`：Subtype（子类型）
* 泛型擦除与补偿
	* 泛型擦除：编译后会将泛型擦除，并使用原始类型代替
	* 使用 `==` 判断 `getClass` 结果为 `true`
	* 可以使用反射添加非泛型指定类型的元素
	* 原始类型：擦除泛型信息后在字节码中的真正类型
		* 无限定的类型变量变为 `Object`
		* 有限定的类型变量变为第一个边界的类型变量
	* 作用：与不支持泛型的旧版本兼容
	* 泛型补偿：
	* 调用泛型方法时，返回类型被擦除，此时会通过获取元素的实际类型进行自动强转，避免抛出类型转换异常
* 泛型通配符
	* 使用泛型时不确定数据类型可以使用泛型通配符：
	* 无限定通配符：`<?>`，可以代表任何数据类型，通常用于声明时的限制情况
	* 上界通配符：`<? extends Type>`，代表该类型为 `Type` 或其子类
	* 下界通配符：`<? super Type>`，代表该类型为 `Type` 或其父类
	* 泛型遵循 PECS（Producer-Extends, Consumer-Super）原则：
	* Producer（生产者）：只读取（生产）数据，使用 `<? extends T>`
	* Consumer（消费者）：只写入（消费）数据，使用 `<? super T>`
	* 既生产又消费：同时读写，使用具体类型 `<T>`
	* 泛型通配符解决了泛型的[[11 多态#11.4 协变、逆变与不变|协变性问题]]：
	* 需要协变时，可以使用上限通配符
	* 需要逆变时，可以使用下限通配符
	* 泛型之间具有不变性，`List<Number>` 和 `List<Integer>` 不存在继承关系
