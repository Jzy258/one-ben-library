# 13 可重入锁

* 可重入锁（重入锁，递归锁）：
	* 一种线程同步机制
	* 一个线程获得锁后，在不释放锁的情况下，仍然可以重复获得同一临界区的锁
	* **优点**：
		* 避免死锁的发生
		* 提高了代码的灵活性和可读性
	* `sychronized` 原生实现可重入锁
	* **原理**：
		* 锁计数器，自动记录获取锁的线程数和重入次数
* `java.util.concurrent.locks.Lock`：
	* `lock()`：
		* 获取锁
		* 获取失败则阻塞线程，不可中断
	* `unlock()`：
		* 释放锁
		* 必须在 `finally` 中调用
		* 与 `lock()` 配对
	* `tryLock()`：
		* 尝试获取
		* 获取成功则返回 `true`
		* 获取失败则返回 `false`，不会阻塞
		* 传入 `time` 和 `unit` 参数可以指定获取超时
	* `lockInterruptibly()`：
		* 可中断获取
		* 等待中可以响应 `interrupt()`，抛出 `InterruptedException`
* `ReentrantLock`：
	* 可重入锁的实现类
	* 实现了 `Lock` 接口
	*  构造方法传入 `true` 参数，可以构造公平锁
* `ReentrantLock`与 `synchronized` 的区别：
	* `ReentrantLock` 需要在 `finally` 语句中手动释放锁
	* 每一个 `lock` 必须保证有 `unlock` 顺利执行，否则会造成死锁
	* `ReentrantLock` 的性能较差
