* 哈希表
	* `key` 部分无序不可重复
	* 添加的 `key` 重复时，`value` 会覆盖
	* 哈希表是数组 + 链表的结合体（或数组 + 红黑树、数组 + 链表 + 红黑树等）
	* 最底层为一维数组 `table`
	* 一维数组的每个元素存储一个单向链表
	* 数据散列分布，所以查询和增删效率都很高
	* `table` 的长度总是 2 的幂
* 存储原理
	* 将 `key` 通过哈希函数转换为哈希值
	* 将哈希值对 `table` 长度取模得到索引值
	* 相同索引值的元素（`key`不同，即发生“哈希碰撞”）挂在当前索引值的链表后
	* `equals()` 和 `hashCode()` 同时重写才能实现正常的哈希碰撞
	* `key` 可以为 `null`
* Java 8 之后的改进
	* Java 8 之前构造方法执行时初始化 `table`，Java 8 后添加第一个元素后初始化数组
	* Java 8 之前在链表头结点插入元素，Java 8 后在链表尾结点插入元素
	* Java 8 之前底层采用数组 + 链表，Java 8 之后采用数组 + 链表 + 红黑树
	* 最开始使用单向链表处理哈希冲突
	* 结点数量 >= 8（树化阈值）且 `table` 的长度 >=64 时链表转换为红黑树
	* 删除红黑树上的节点后，结点 <=6（非树化阈值）时红黑树转换为链表
* HashMap 的容量总是 2 的幂
	* 加快哈希计算
	* 位运算比取模速度快
	* 可以用 $2^n$ 和 `hash` 进行与运算来代替取模运算，效率更高
	* 减少哈希冲突
	* 使用 $2^{n}-1$ 进行与运算可以确保结果（`table` 的下标）既有奇数又有偶数，使散列更加均匀
* 初始化容量的设置
	* 哈希表中元素越来越多时，散列碰撞的几率就越来越高（数组长度固定），导致单链表过长，此时需要对哈希表扩容
	* 执行 `put()` 时，如果 `HashMap` 中存储元素的个数超过数组长度 `loadFactor`（`loadFactor` 指负载因子，默认值为 0.75），就需要数组扩容
	* 扩容：将数组长度扩大一倍，遍历哈希表中元素，把这些元素重新均匀分散到扩容后的哈希表中；非常消耗性能
	* 为了避免性能损坏，建议使用哈希表之前，先预测元素个数，提前设置合适数组长度，避免扩容
