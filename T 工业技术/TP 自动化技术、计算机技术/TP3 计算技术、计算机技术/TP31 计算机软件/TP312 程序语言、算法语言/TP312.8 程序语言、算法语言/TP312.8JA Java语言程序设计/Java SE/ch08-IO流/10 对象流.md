* 序列化（Serial）：
* 为了方便使 Java 对象在网络中传输，将其转换为字节序列
* 通过 `ObjectOutputStream` 实现
* 反序列化（Deserial）：
* 将字节序列转换为 Java 对象
* 通过 `ObjectInputStream` 实现
* 使用方法：
* `writeObject(Object obj)`：将 Java 对象写出到文件 / 网络
* `readObject()`：从文件 / 网络读取 Java 对象
* `Serializable` 接口：
* 被序列化和反序列化的对象必须实现标志接口 `java.io.Serializable`
* 未实现该接口的对象试图序列化时抛出 `NotSerializableException`
* 序列化版本号：
* 编译器会为实现 `Serializable` 接口的类添加 `serialVersionUID` 属性
* Java 通过类名 + 序列化版本号区分不同的类
* `serialVersionUID` 是一种安全机制：
	* 反序列化时，JVM 检查存储 Java 对象的文件中 `class` 的序列化版本号是否和当前 Java 程序一致
	* 一致则可以反序列化，否则报错
* 实现 `Serializable` 接口的类建议显式定义序列化版本号：
	```java
	private static final long serialVersionUID = 1L;
	```
	* 类可能在开发中修改，重新编译
	* 编译器会为没有显式定义序列化版本号的类重新分配新的版本号，导致之前序列化的对象无法反序列化
	* 使用 `@java.io.Serial` 注解标注，可以使用 IDEA 随机生成序列化版本号
* 不参与序列化的属性需要使用瞬时关键字 `transient` 修饰
* 适用于敏感信息、临时数据等
* 静态字段属于类，不会被序列化
* 父类序列化：
* 父类实现 `Serializable`，子类则也可以序列化
* 父类未实现 `Serializable`，则父类字段不会序列化，反序列化时会调用父类的无参构造方法初始化
