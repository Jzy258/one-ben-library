* UML
	* 统一建模语言（Unified Modeling Language, UML）：用于模型化和软件系统开发开发的图形化语言，为软件开发的所有阶段提供模型化和可视化支持
	* 模型图包括：
	* 用例图：描述系统的功能需求和用户与系统之间的关系
	* 静态图：
		* 类图：描述软件系统的类、接口、关系及其属性等
		* 包图
		* 对象图
	* 行为图：
		* 状态图：描述类或对象的生命周期以及状态之间的转换
		* 活动图
	* 交互图：
		* 顺序图（序列图）：描述对象之间交互、消息传递和时序约束等
		* 协作图
	* 部署图
	* 常用软件：StarUML（开源）等
* 类之间的关系
	* ![[3.4.png]]
	* 继承关系（泛化关系，Generalization，IS-A）：
	* 类和子类的关系，接口和子接口的关系
	* 子类、子接口继承父类、父接口的功能，并且可以增加它自己的新功能
	* `extends`
	* 空心箭头-实线-指向父类（父接口）
	* 实现关系（Realization，IS-LIKE-A）：
	* 类和接口之间的关系
	* 一个类可以实现多个接口，实现接口的所有功能；体现了**规范**与**实现**分离的原则
	* `implements`
	* 空心箭头-虚线-指向接口
	* 依赖关系（Dependency）：
	* 类 A 使用类 B 的功能，具有偶然性、临时性，非常弱
	* 类 B 的变化会影响到类 A
	* 类 B 作为类 A 的方法的参数（或局部变量）
	* 箭头-虚线-指向类 A
	* 关联关系（Association）：
	* 比依赖关系强，必然的，长期的
	* 类 A 含有类 B 类型的属性
	* 可以分为单向关联、双向关联；可以分为一对一关联、一对多关联、多对多关联；包括两个类的关联和一个类与自身关联
	* 箭头-实线-指向类 B，双向关联可以取消两个箭头；在关联的两端可以标注双方的角色和多重性标记
	* 聚合关系（Aggregation，HAS-A）：
	* 关联关系的一种特例
	* 整体与部分的关系；一个类包含、合成或拥有另一个类的实例，整体与部分可以分离；整体与部分的生命周期不同
	* 类 A 含有类 B 类型的属性
	* 空心菱形-实线-指向类 A
	* 组合关系（Composition，CONTAINS-A）：
	* 关联关系的一种特例
	* 整体与部分的关系；一个类包含、合成或拥有另一个类的实例，只能存在于一个整体对象中；整体与部分的生命周期相同
	* 类 A 含有类 B 类型的属性
	* 实心菱形-实线-指向类 A
* 总结
	* 继承和实现一般没有争议
	* 后四种关系的强弱比较：组合>聚合>关联>依赖
