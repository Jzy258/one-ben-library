* JVM 体系结构
	* JVM 对应一套规范（Java 虚拟机规范），可以有不同的实现
	* HotSpot：Oracle 开发，最常用的虚拟机实现，默认的 Java 虚拟机，默认包含在 Oracle JDK 和 OpenJDK 中
	* 其他常见的 JVM 实现：JRockit，IBM JDK，Azul Zing，OpenJ9...
	* 运行时数据区：
	* PC 计数器：较小，记录正在执行的字节码指令的地址
	* Java 虚拟机栈：用于存储栈帧，栈帧用于存储局部变量表、操作数栈、动态链接、方法出口等信息
	* 堆：最大，存储 Java 对象实例及数组，是垃圾收集器收集垃圾的主要区域
	* 方法区：存储已被虚拟机加载的类信息、常量、静态变量、即时编译器编译后的代码等
	* 运行时常量池：方法区的一部分，存储编译期生成的各种字面量与符号引用（类名、属性名、方法名）
	* 本地方法栈：本地方法执行过程使用，与 Java 虚拟机栈相似
	* 元空间：HotSpot 实现的方法区（Java 8 后）
* Java 6 的 HotSpot
	* HotSpot 结构：
	* ![[3.2.png]]
	* 本地方法：`native` 修饰的、以 `;` 结尾的方法，调用 C++ 编写的动态链接库
	* 年轻代：存储刚创建的对象
	* 老年代：存储经过垃圾回收之后仍然存活的对象
	* 方法区实现为永久代
	* 这个时期永久代和堆是相邻、连续的，但内存空间是隔离的，永久代的垃圾收集和老年代捆绑在一起，无论谁满了都会触发永久代和老年代的垃圾收集
* Java 7 的 HotSpot
	* 类的静态变量和字符串常量池转移到堆中了
	* 运行时常量池中的符号引用转移到本地内存了
	* 原因：永久代存储过多，易发生OOM（内存溢出）错误
* Java 8 后的 HotSpot
	* 彻底移除永久代
	* 将方法区移到本地空间，实现元空间
	* 将符号引用重新放回运行时常量池
* Java 程序的执行原理
	* ![[3.3.png]]
	* 编译阶段：
	* 编写 .java 文件
	* 通过 `javac` 命令检查语法错误，编译为 .class 字节码文件
	* 运行阶段：
	* 通过 `java` 命令运行
	* 类加载器根据 `CLASSPATH` 寻找 .class 文件
	* 加载 .class 文件到内存
	* 链接：
		* 验证，确保符合 Java 语言规范和安全规范
		* 准备，为静态变量分配内存空间并初始化
		* 解析，将符号引用转换为直接引用（内存地址）
	* 执行类的静态代码块
	* 执行 `main` 方法
	* 执行完毕且不需要该类时释放内存
	* 解释执行供操作系统运行
	* 操作系统与硬件交互
