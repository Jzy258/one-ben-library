# 10 线程安全问题

* 线程安全问题：
	* **定义**：
		* 多个线程同时修改同一个共享资源，导致出现不正确的结果或抛出异常
	* 局部变量一般不会被共享，不存在线程安全问题
	* 多个线程并发的执行顺序和执行时间不确定，可能导致线程安全问题
	* 线程安全问题通常通过加锁机制来解决
		* 线程同步机制：线程排队执行
		* 线程异步机制：线程各自执行
	* 
* 同步代码块
	* **原理**：
		* 将一段代码标记为临界区，同一时间只能有一个线程进入该临界区并执行
		* 其他线程需要等待当前线程执行完毕后才能进入临界区
	* **本质**：
		* 互斥锁的实现
	* **语法**：
      ```java
      synchronized (锁对象) {
      // 临界区
      }
      ```
	* **原理**：
		* 每个对象都有一个监视器（锁），进入同步代码块时会尝试获取该对象的监视器
		* 如果获取成功，则可以进入临界区执行，执行完毕后释放监视器
		* 如果获取监视器失败，则需要等待其他线程释放监视器后再次尝试获取
	* 使用规范：
		* 同步代码块应该尽可能简短，只包含对共享资源的操作
		* 同步代码块中的锁对象应该尽可能唯一，避免多余的竞争和等待
		* 同步代码块中的操作应该尽可能快速，避免影响程序的响应性和效率
* 同步实例方法：
	* 使用 `synchronized` 关键字指定锁对象，对方法加锁，确保同一时间只有一个线程可以访问该实例方法
	* **原理**：
		* 获取当前对象的监视器并加锁
	* 不同的实例可以并发执行同步实例方法，不会相互干扰
	* 使用同步实例方法时，同一对象上的其它**同步方法**会被阻塞，非同步方法不会被阻塞
* 同步静态方法：
	* 用 `synchronized` 修饰静态方法，线程执行时会找类锁
	* 通常用于保护静态变量的安全
* 死锁
	* 成立条件：
		* 互斥：
			* 资源同时只能被一个线程占用
		* 持有并等待：
			* 持有资源的线程等待别的资源
		* 不可剥夺：
			* 线程持有的资源只能主动释放
		* 循环等待：
			* 持有-等待链形成闭环
	* 避免策略：
		* 一次性申请所有资源：
			* 降低并发
		* 允许超时放弃：
			* `Lock` 可实现
		* 统一加锁顺序
	* 排查工具：
		* `jps`：
			* 获取当前运行的 Java 进程 PID
		* `jstack PID`：
			* 检查死锁，并输出等待的锁
