# 03 @Transactional的属性

* `propagation`：
	* **作用**：
		* 控制事务的传播行为，即当 `a` 方法调用 `b` 方法，且 `a` 和 `b` 都有事务时事务如何传递
	* **可选值**：
		* `REQUIRED`：
			* 支持当前事务，若不存在则新建事务
		* `SUPPORT`：
			* 支持当前事务，若不存在则以非事务方式运行
		* `MANDATORY`：
			* 必须运行在一个事务中，若不存在则抛出异常
		* `REQUIRES_NEW`：
			* 开启一个新事务，若已存在则挂起
		* `NOT_SUPPORTED`：
			* 以非事务方式运行，若已存在则挂起
		* `NEVER`：
			* 以非事务方式运行，若已存在则抛出异常
		* `NESTED`：
			* 若已存在则运行在嵌套事务中，被嵌套事务独立提交或回滚；若不存在则新建事务
			* 外层回滚会导致内层回滚
* `isolation`：
	* 控制事务的隔离级别
	* 可选值：
		* `READ_UNCOMMITED`：读未提交
		* `READ_COMMITED`：读提交
		* `REPEATABLE_READ`：可重复读
		* `SERIALIZABLE`：序列化
* `timeout`：
	* 设置事务超时时间
	* 若事务中 SQL 执行超时，则即使事务成功也回滚
* `readOnly`：
	* 当可以确保事务中仅含纯 DQL 语句时，可以设置 `readOnly = true`
	* 作用：
		* ORM 框架能够开启性能优化：
			* 跳过事务提交时的脏检查
		* 声明代码意图：
			* 增强可读性
			* 在数据库读写分离的架构中，将查询操作自动指向从库，减轻主库压力
* `rollbackFor` 和 `noRollbackFor`：
	* **作用**：
		* 指定异常回滚规则
	* **默认行为**：
		* 遇到运行时异常和错误时回滚，遇到受检异常时不回滚
	* **参数值**：
		* 异常的 `class` 对象
