* 密码加密：
	* 密码使用 BCrypt 算法加密
	* 每次 `encode()` 掺入随机盐
		* 同密码加密所得的密文不同
		* 可以防止彩虹表攻击
	* 使用 `matches()` 验证
		* 不使用 `equals()`
	* 成本因子：
		* 指定 BCrypt 算法的强度
		* 强度越高，密文生成越慢，越安全
	* 可升级：
		* 接口返回 `PasswordEncoder`，换算法成本低
	* 更安全的算法：
		* `Argon2`、`SCrypt`
* CSRF（跨站请求伪造）：
	* **攻击原理**：
		* 用户登录 A 网站后得到会话 Cookie
		* 用户访问恶意网站，Cookie 被恶意网站截留
		* 恶意网站以该用户的名义向 A 网站发送请求
		* 服务器无法分辨是否用户本人操作
	* 使用 JWT：
		* token 必须由 JS 代码显式设置，不会自动携带
		* 攻击者无法获取到 token，无法伪造认证
		* CSRF 失效
	* **结论**：
		* 使用 Cookie 认证必须开启 `CSRF`
		* 使用 Bearer Token 认证可以关闭
* CORS（跨域资源共享）：
	* 同源：
		* 协议 + 域名 + 端口相同
	* 前后端端口不同，不同源
	* 响应头带 `Access-Control-Allow-Origin`，则浏览器放行跨域请求
	* 后端配置 CORS：
		* 添加 `CorsConfigurationSource` bean
			* `CorsConfiguration`：
				* 用于配置 CORS 的实例
				* `setAllowedOrigins`：
					* 指定允许放行的源
				* `setAllowedMethod`：
					* 指定放行的请求方式
				* `setAllowedHeaders`：
					* 指定放行的请求头
			* `UrlBasedCorsConfigurationSource`：
				* `registerCorsConfiguraton`：
					* 配置生效的路径
		* 在 `SecurityConfig` 中配置 `cors`
	* 对于简单请求（GET / POST 表单），直接发送即可
	* 带有自定义头的请求，会先发送 OPTIONS 预检：
		* **本质**：
			* 发送另一次请求
		* 询问服务器：
			* `Access-Control-Request-Headers`：
				* 本次请求的自定义头
			* `Access-Control-Request-Method`：
				* 本次请求的方法
		* 服务器响应的头：
			* `Access-Control-Allow-Headers`：
				* 是否允许该自定义头
			* `Access-Control-Allow-Methods`：
				* 是否允许该请求方法
			* `Access-Control-Allow-Origin`：
				* 允许访问的源
* XSS（跨站脚本）：
	* **原理**：
		* 将 `<script>` 注入页面，从而窃取 token / Cookie / 伪造操作
	* MIME 嗅探：
		* 老旧或配置错误的 Web 服务器会将所有资源统一标记为 `application/octet-stream` 或 `text/plain`
		* 浏览器为了保证读取正确，会忽略 `Content-Type` 响应头，读取资源文件的前几个字节，根据特征判断文件真实类型
		* 攻击者在非文本文件的开头注入 `<script>` 脚本，浏览器嗅探后作为文本处理，导致 XSS 攻击
	* 防护措施：
		* 前端：
			* Vue 的模板默认转义
			* 不使用 `v-html` 渲染用户输入
		* 后端：
			* 对用户输入做校验 / 白名单
			* 不信任任何输入
		* HTTP 层：
			* Spring Security 默认加 `X-Content-Type-Options`，防止 MIME 嗅探
* 安全响应头：
	* Spring Security 默认为每个响应添加安全响应头
	* `X-Content-Type-Options: nosniff`：
		* 防浏览器 MIME 嗅探执行恶意脚本
	* `X-Frame-Options: DENY`：
		* 防点击劫持
		* 防止攻击者使用 `iframe` 嵌入该页面
	* `Cache-Control: no-cache`：
		* 防敏感响应被缓存
