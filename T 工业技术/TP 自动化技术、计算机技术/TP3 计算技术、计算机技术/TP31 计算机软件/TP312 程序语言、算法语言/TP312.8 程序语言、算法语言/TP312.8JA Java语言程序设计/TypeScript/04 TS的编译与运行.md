* TS 无法直接运行，必须先被“编译”为 JS，再由 JS 引擎运行
* 编译阶段：
	* `tsc`（TypeScript Compiler）：
		* 读取当前目录下的 `tsconfig.json` 配置，编译整个项目
		* `-w` / `--watch`：监听模式
			* 文件保存时自动编译
		* `--noEmit`：
			* 只做类型检查，不生成 JS 文件
			* 用于验证代码是否通过类型校验，而不污染输出目录
		* `--init`：
			* 生成 `tsconfig.json` 模板文件
		* 类型检查：
			* 扫描所有 `.ts` 文件并校验类型契约是否被遵守
		* 类型擦除（Type Erasure）：
			* 将所有类型注解删除
			* 将现代 ES 语法降级为指定的旧版本
	* `tsconfig.json`：
		* `tsc` 的配置
		* `target`：目标 JS 版本
			* 指定 TS 代码被编译成哪个版本的 JS
		* `module`：模块规范
			* 指定编译后使用哪种模块导入语法
			* **可选值**：
				* `CommonJS`【Node.js 一般选择】
				* `ESNext`
		* `strict`：
			* 是否开启 `noImplicitAny`、`strictNullChecks` 等严格检查机制
* 运行阶段：
	* 使用浏览器或 Node.js 执行纯净 JS
* 主流的开发运行模式：
	* 原生编译：
		* `tsc -w` 监听编译
		* `nodemon` 监听项目文件变化，修改时自动重启应用
	* 即时执行：
		* `ts_node`：
			* 直接在内存中编译并执行，不生成物理 JS 文件
		* 生产环境不建议使用
	* 构建工具集成：
		* 利用 `esbuild` 或 `swc` 在开发服务器启动时按需编译，改动代码时毫秒级热更新
		* 最终打包上线时才会生成完整 JS 文件
* **注意事项**：
	* 运行时没有类型校验
	* 运行时报错的行号指向编译后的文件，难以调试
		* 在 `tsconfig.json` 中开启 `"sourceMap": true`
		* 浏览器 / Node 报错能直接映射回源文件行号
* `npm`：
	* Node.js 的包管理工具
	* **功能**：
		* 依赖管理：
			* 自动从注册表下载需要的 JS 库
		* 版本控制：
			* 通过 `package.json` 记录项目所依赖的包及其版本号，确保版本一致
		* 脚本运行：
			* 在 `package.json` 中自定义脚本命令，`npm` 会自动执行
	* `npm init`：
		* 以交互的形式初始化当前项目，生成核心配置文件 `package.json`
	* `npm install`：
		* 安装 JS 库
		* `-g`：
			* 将包安装到全局环境中，而不是某一个具体的项目文件夹中
		* 会安装到当前目录的 `node_modules`
		* 同时会在 `package.json` 中添加相关依赖
