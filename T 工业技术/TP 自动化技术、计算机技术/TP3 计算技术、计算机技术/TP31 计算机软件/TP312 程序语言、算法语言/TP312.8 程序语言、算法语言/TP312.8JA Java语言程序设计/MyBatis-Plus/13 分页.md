* 分页：
	* **作用**：
		* 只查询特定页的数据
	* **原理**：
		* 通过 `PaginationInnerInterceptor` 实现
		* 利用拦截器机制，在 SQL 执行前动态改写
			* 自动生成 `SELECT COUNT(*)` 语句，获取满足条件的总记录数
			* 在原 SQL 后添加特定的分页语句，只查询当前页的数据
	* **实现步骤**：
		* 在配置类中编写 `MybatisPlusInterceptor` Bean
			* 在其中注册 `PaginationInnerInterceptor`
			* 注册时传入 `DbType` 以适应不同数据库方言
		* 执行查询方法时，新建 `Page` 对象，传入当前页和每页条数对象
		* 调用 `IService` 提供的 `page` 方法，传入 `Page` 对象和 `Wrapper`
	* `Page` 对象：
		* 分页模型，实现了 `IPage` 接口
		* **核心属性**：
			* `records`：
				* 当前页的数据列表
			* `total`：
				* 总记录数
			* `size`：
				* 每页显示条数
				* 默认为 10
			* `current`：
				* 当前页码
				* 默认为 1
			* `order`：
				* 排序信息
			* `searchCount`：
				* 本次分页是否执行 `COUNT` 查询获取总记录数
				* 可以通过 `Page` 对象的构造方法或 `setSearchCount` 设置
				* 默认为 `true`
			* `optimizeCountSql`：
				* 是否对 `COUNT` 进行智能优化
				* 默认为 `true`
				* **优化逻辑**：
					* 开启时，MyBatis-Plus 会尝试简化 `COUNT` 语句
						* 移除 `ORDER BY`
						* 移除不参与 `WHERE` 条件的 `LEFT JOIN` 表
				* **适用场景**：
					* 绝大多数场景
					* 除非 `COUNT` 语句执行结果不准确或解析优化失败
	* 自定义分页：
		* 在 Mapper 接口中定义方法，第一个参数必须为 `Page`
		* xml 中只编写业务逻辑，无需关心分页语法
		* 调用时传入 `Page` 对象，则自动完成分页
	* **配置**：
		* `PaginationInnerInterceptor`：
			* `overflow`：
				* 请求页码超过总页数时是否自动将页码重置为第 1 页
				* 否则返回无数据页
			* `maxLimit`：
				* 单页条数上限
		* 临时不分页：
			* 将 `Page` 的 `size` 设为小于 0
* MP 转换：
	* **解决问题**：
		* 将分页查询所得结果（Entity）转换为视图对象（VO）的问题
	* `IPage#convert`：
		* 利用 `IPage` 不关注泛型具体类型的性质实现
		* 传入 Lambda 表达式，定义从 Entity 到 VO 的转换逻辑，返回一个新的 `IPage<VO>`
	* `BeanUtils.copyProperties`：
		* **作用**：
			* 快速将属性相同的 Entity、DTO、VO 互相转换
	* 请求参数封装：
		* 通常编写 `PageQuery` 类封装前端传入分页相关参数
		* 提供 `build` 或 `toPage` 等方法转换成 `Page` 对象
