* 逻辑删除：
	* 不实际删除数据库中的记录，而是通过标记字段（如 `deleted`）来表示数据是否已被删除
	* **作用**：
		* 保护数据，防止数据因误操作而丢失
		* 便于后续数据的审计或恢复
	* **原理**：
		* MyBatis-Plus 会在底层改写 SQL
		* 删除操作：
			* 将 `DELETE` 语句替换为 `UPDATE` 语句，将标记字段 `deleted` 的值设为 `1`
		* 查询操作：
			* 在 `SELECT` 语句后追加 `AND deleted = 0` 条件
		* 更新操作：
			* 在 `UPDATE` 语句后追加 `AND deleted = 0` 条件
	* **配置方法**：
		* 全局配置：
			* `mybatis-plus.global-config.db-config.logic-delete-field`：
				* 指定逻辑删除字段名
			* `mybatis-plus.global-config.db-config.logic-delete-value`：
				* 指定已删除值
			* `mybatis-plus.global-config.db-config.logic-not-delete-value`：
				* 指定未删除值
		* 注解配置：
			* 在 Entity 的逻辑删除字段上添加 `@TableLogic` 注解
				* 注解的优先级高于全局配置
			* 指定 `value` 和 `deval` 属性
	* **注意事项**：
		* 逻辑删除字段推荐使用 `Integer`、`Boolean` 或 `LocalDateTime`
			* 若使用日期类型，可将未删除值设为 `null`，已删除值设为 `now()`
		* Mapper.xml 中自定义的 SQL 不会被自动拦截
		* 不能通过 `update` 方法修改 `deleted` 字段：
			* `update` 生成的 SQL 会自动移除对 `deleted` 字段的操作
			* `update` 生成的 SQL 本身会添加 `deleted = 0` 的条件
		* 若业务字段有唯一索引，逻辑删除后插入相同数据会报错
			* 建议将逻辑删除字段包含在唯一索引中
		* 极少数情况下可以使用 `@IntercepterIgnore` 注解临时忽略逻辑删除
