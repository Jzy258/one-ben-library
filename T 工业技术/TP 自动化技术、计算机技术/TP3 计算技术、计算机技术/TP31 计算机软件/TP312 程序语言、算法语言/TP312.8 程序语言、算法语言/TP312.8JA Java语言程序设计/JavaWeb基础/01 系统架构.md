系统架构包括：
* C/S 架构
* B/S 架构

C/S 架构：
* Client / Server（客户端 / 服务器）
* 特点：需要安装特定的客户端软件
* 优点：
	* 速度快、服务器压力小：软件中的数据大部分集成到客户端软件中，很少数据从服务器端传送过来
	- 界面酷炫：使用专门语言实现界面，更加灵活
	* 安全：客户端有很多个，服务器虽然只有一个，服务器受损问题也不大，因为大量的数据在多个客户端上有缓存
* 缺点：
	* 难以升级维护：麻烦，成本较高，每一个客户端软件都需要升级

B/S 架构：
* Browser / Server（浏览器 / 服务器）
* 本质还是一个 C/S，只不过 C 是一个固定不变浏览器软件
* 优点：
	- 升级维护方便，成本较低（只需要升级服务器端）
	- 不需要安装特定的客户端软件，用户操作方便
- 缺点：
	- 速度慢：不是因为带宽低，是因为所有数据都在服务器上，用户发送的每一个请求都需要服务器响应，B/S 结构系统在网络中传送的数据量较大
	- 体验差：界面不酷炫，因为浏览器只支持 HTML CSS JavaScript
	- 不安全：所有的数据都在服务器上，服务器损坏会导致数据全部丢失

不同结构的系统在不同的业务场景下有不同的适用场景：
* 娱乐性软件：C/S 结构
- 公司内部使用的一些业务软件：B/S 结构
	* 维护成本低
	- 不需要酷炫
	* 能够进行数据的维护即可
