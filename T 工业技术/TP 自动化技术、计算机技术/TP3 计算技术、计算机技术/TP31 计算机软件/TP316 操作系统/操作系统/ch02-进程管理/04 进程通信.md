进程间通信（Inter-Process Communication，IPC）：
* 两个进程之间产生数据交互

进程是分配系统资源（包括内存地址空间）的单位，因此各进程拥有的内存地址空间相互独立

为了保证安全，一个进程不能直接访问另一个进程的地址空间

进程通信方式：
* 共享存储
* 消息传递
* 管道通信

共享存储
* 分配一块内存用于进程间存放共享数据
* 各个进程对共享空间的访问是互斥的（可使用内核提供的同步互斥工具，如 P、V 操作）
* 通过增加页表项 / 段表项即可将同一片共享内存映射到各个进程的地址空间中
* Linux 中实现共享内存：
```c
int shm_open(...); // 通过 shm_open 系统调用，申请一片共享内存区
void *mmap(...); // 通过 mmap 系统调用，将共享内存空间映射到自己的地址空间
```
* 基于数据结构的共享：
	* 共享空间为一种数据结构
	* 速度慢、限制多
	* 低级通信
* 基于存储区的共享：
	* 数据的形式、存放位置由通信进程决定
	* 速度快
	* 高级通信

消息传递
* 进程间的数据交换以格式化的消息（Message）为单位
* 进程通过操作系统提供的发送消息、接收消息原语进行数据交换
* 消息结构：
	* 消息头：
		* 发送进程 ID
		* 接收进程 ID
		* 消息长度
	* 消息体
* 直接通信：消息发送进程指明接收进程的 ID
	* 进程 `P` 调用发送原语 `send(Q, msg)`，向进程 `Q` 发送消息 `msg`
	* 进程 `Q` 调用接收原语 `receive(P, &msg)`，从进程 `P` 处接收消息 `msg`
* 间接通信：通过信箱间接通信
	* 进程 `P` 调用发送原语 `send(A, msg)`，向信箱 `A` 发送消息 `msg`
	* 进程 `Q` 调用接收原语 `receive(A, &msg)`，从信箱 `A` 接收消息 `msg`
	* 多个进程可以向同一个信箱发送消息或从同一个信箱接收消息

管道通信：
* 管道（Pipe）：内核维护的、大小固定的内存缓冲区（通常几 kB 到几十 kB）
* 通信原理：进程 P 向管道内写数据，进程 Q 从管道读数据
* 特点：
	* 符合 FIFO 原则
	* 半双工通信：同一时间段只能单向传输，双向同时通信需要两个管道
	* 进程互斥访问：管道写满，写进程阻塞；管道读空，读进程阻塞
* 管道中的数据读出后立即销毁
	* 一个管道允许多个写进程和一个读进程（Linux 允许多个读进程轮流读数据）
* 管道没空，则读进程可以读数据；管道没满，则写进程可以写数据
* 应用：
	* 在命令行中使用 `|` 连接两个命令，将左边命令的标准输出（stdout）直接传给右面命令的标准输入（stdin）

标准输入 / 输出 / 错误：
* OS 为每个进程预先打开的数据通道，用于接受输入、输出正常结果、输出错误信息
* 文件描述符：
	* stdin：0
	* stdout：1
	* stderr：2
* 默认情况：
	* stdin 连接到键盘，表现为程序等待打字输入
	* stdout 连接到屏幕，表现为程序将输出内容显示在屏幕上
	* stderr 连接到屏幕，表现为程序将错误信息显示在屏幕上
* 重定向：
	* 在 Shell 中，可以使用符号改变通道的目标
	* 常用重定向操作：
		* `>`：重定向 stdout 到文件，覆盖原内容
		* `>>`：追加 stdout 到文件
		* `2>`：重定向 stderr 到文件
		* `&>`：重定向 stdout 和 stderr 到同一文件
		* `<` 重定向 stdin 来自文件
		* `> nul`、`2> nul`：丢弃所有输出
* 管道

通信方式：
* 单工（Simplex）：
	* 单向通信，固定发送端和接收端
* 半双工（Half-Duplex）：
	* 双向通信，但同一时间段只能单向
* 全双工（Full-Duplex）：
	* 双向通信，可以同时双向
