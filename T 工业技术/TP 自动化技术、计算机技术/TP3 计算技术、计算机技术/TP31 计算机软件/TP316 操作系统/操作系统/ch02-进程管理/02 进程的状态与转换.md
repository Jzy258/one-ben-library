创建态（New，新建态）：
* 进程被创建时的状态
* 该阶段操作系统为进程分配资源、初始化 PCB
* 进程创建完成（-> 就绪态）

就绪态（Ready）：
* 创建完成
* 已经获取运行所需资源，具备运行条件
* 尚未获得空闲 CPU
* 系统中可能会有多个进程处于就绪态
* 进程被调度（-> 运行态）

运行态（Running）：
* 获取到 CPU，正在运行
* CPU 空闲时，操作系统会选择一个就绪态进程变为运行态
* 在获得所需资源之前，进程无法运行
* 单（核）CPU 同一时刻只会有一个进程处于运行态
* 时间片用尽或 CPU 被抢占（-> 就绪态）
* 进程用系统调用申请某种系统资源或请求等待某种事件发生（主动地）（-> 阻塞态）
* 进程运行结束或遇到不可修复的问题（-> 终止态）

阻塞态（Blocked/Waiting）：
* 运行过程中请求等待某事件发生
* 进程失去 CPU，CPU 选择其他就绪态进程运行
* 申请的资源被分配或等待的事件发生（被动地）（-> 就绪态）

终止态（Terminated）：
* 进程执行 `exit` 系统调用，请求操作系统终止该进程
* 进程失去 CPU，回收内存空间，回收 PCB

不能由阻塞态直接转换为运行态，也不能由就绪态直接转换为阻塞态

进程的基本状态：
* 运行态、就绪态、阻塞态
* 进程的整个生命周期大部分时间处于三种基本状态

进程 PCB 中有一个整型变量 `state` 表示进程的当前状态，操作系统将处于同一种状态的进程统一管理，并将 PCB 组织起来

进程的组织：
* 链接方式：按照进程状态将 PCB 分为多个队列，操作系统持有各个队列的指针
	* 执行指针：指向处于运行态的进程
	* 就绪队列指针：指向处于就绪态的进程，通常将优先级高的进程放在队头
	* 等待 I/O 的阻塞队列指针、等待磁盘的阻塞队列指针...
* 索引方式：按照进程状态建立索引表，操作系统持有各个索引表的指针
	* 执行指针 -> PCB
	* 就绪表指针 -> 就绪索引表（索引 -> PCB，索引 -> PCB，...）
	* 阻塞表指针 -> 阻塞索引表（索引 -> PCB，索引 -> PCB，...）
