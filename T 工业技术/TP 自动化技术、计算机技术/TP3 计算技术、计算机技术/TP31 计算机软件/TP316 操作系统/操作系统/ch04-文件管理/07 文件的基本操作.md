读 / 写指针记录了进程对文件读 / 写操作进行到的位置

打开文件：
* `Open` 系统调用
* 根据路径读入目录
* 找到目标文件的 FCB，复制到系统打开目录表
* 在进程打开目录表中新建项，返回文件描述符

关闭文件：
 * `Close` 系统调用
 * 将进程的打开文件表中对应表项删除
 * 回收分配给该文件的内存等资源
 * 系统打开文件表的打开计数器减 1，为 0 时删除对应表项

读文件：
* `Read` 系统调用
* 参数：
	* 文件描述符
	* 指明读入数据大小
	* 读入的数据放在内存中的什么位置
* 读指针

写文件：
* `Write` 系统调用
* 参数：
	* 文件描述符
	* 指明写出数据大小
	* 写出的数据放在内存中的什么位置
* 写指针

---
打开文件表：
* 内核维护的一组表项
	* 每个表项记录一个**已打开**文件的状态信息（当前读写位置、打开模式、指向底层文件的指针等）
* 打开文件时，内核会在打开文件表中创建新条目，返回整数句柄（文件描述符或 handle）
* 现代操作系统通常采用两级表：
	* 系统级：打开文件表（Open File Table）
		* 记录每个打开文件的全局信息（当前偏移量、打开计数、打开模式等）
		* 每个条目包含：
			* 当前文件偏移量（当前读写位置）：使用 `lseek` 修改
			* 打开计数（Reference Count）：指向此条目的文件描述符数
			* 打开模式：只读 / 只写 / 读写
			* 指向 v-node / inode 的指针
		* 存放于内核的全局区域
	* 进程级：文件描述符表（FD Table）
		* 记录该进程打开的所有文件描述符
		* 本质：数组类似结构
			* 索引即文件描述符
		* 每个条目包含：
			* 指向系统级打开文件表项的指针
			* 其他标志
		* 存放于 PCB 中
* 作用：
	* 偏移量独立：多个进程打开同一文件，各自维护读写位置，互不干扰
	* 共享访问：通过 `dup` 或 `fork` 实现共享偏移量
	* 权限检查
	* 引用计数
	* 实现设备、套接字、管道的统一管理
