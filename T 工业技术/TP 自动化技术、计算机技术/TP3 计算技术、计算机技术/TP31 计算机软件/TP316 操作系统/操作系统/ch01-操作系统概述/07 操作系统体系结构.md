# 07 操作系统体系结构

计算机系统层次结构：
* 用户
* 应用程序、用户
* 操作系统
	* 非内核功能（如 GUI）
	* 内核（大内核）
		* 进程管理、存储器管理、设备管理等
		* 微内核：时钟管理、中断处理、原语（设备驱动、CPU 切换等）
* 裸机

操作系统的内核运行在内核态
操作系统的非内核功能运行在用户态

分层结构：
* 内核分为多层，内层可**单向**调用**相邻**的**更低**一层的接口
* 最底层为 0 层
* 优点：
	* 便于调试，自底向上逐步验证
	* 结构清晰，易于维护和扩展
* 缺点：
	* 仅可直接调用相邻层，效率低，系统调用时间长
	* 难以合理界定各层边界

模块化：
* 将内核划分为多个模块，各模块间相互协作
* 内核 = 主模块（只负责核心功能） + 可加载内核模块（动态加载，无需重新编译）
* 优点：
	* 模块间逻辑清晰，易于维护，可多模块同时开发
	* 可动态加载模块，增强 OS 的适应性
	* 模块间直接调用，无需采用消息传递通信，效率高
* 缺点：
	* 模块间接口未必合理实用
	* 模块间耦合性强，难以调试和验证

宏内核（大内核，如 Linux、UNIX）：
* 所有系统功能都放在内核里（通常也采用模块化思想）
* 优点：
	* 性能高，内核内部各种功能都可以直接相互调用
* 缺点：
	* 内核大功能复杂，难以维护
	* 某个功能出错可能导致整个系统崩溃

微内核（如 Windows NT）：
* 只把中断、原语、进程通信等最核心的功能放入内核，其他功能（进程管理、文件关管理、设备管理等）以用户进程的形式运行在用户态
* 优点：
	* 内核小功能少，易于维护，可靠性高
	* 内核外的某个功能出错不会导致整个系统崩溃
* 缺点：
	* CPU 状态的切换需要消耗时间，频繁切换状态会导致系统性能下降
	* 用户态的各功能模块不能直接相互调用，必须通过内核的消息传递机制间接通信

外核（Exokernel）：
* 负责为用户进程分配未经抽象的硬件资源，并保证资源使用安全
* 优点：
	* 直接分配不虚拟、不抽象的硬件资源，使用户进程可以更灵活地使用
	* 减少了虚拟硬件资源的映射层，提高效率
* 缺点：
	* 降低了系统的一致性，导致内存方式不同
	* 使系统变得更复杂
