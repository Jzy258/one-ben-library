# 03 IO控制方式

I/O 控制方式：
* 程序直接控制方式
* 中断驱动方式
* DMA 方式
* 通道控制方式

评价：
* 完成一次读 / 写的流程
*  CPU 干预的频率
* 数据传送的单位
* 数据的流向
* 优缺点

程序直接控制方式（轮询）：
* 完成一次读 / 写的流程：
	* CPU 向控制器发出读指令，设备启动并将状态寄存器设为未就绪
	* CPU 轮询检查控制器的状态，并处理可能的错误（CPU：你好了吗你好了吗你好了吗你好了吗...）
	* 设备就绪后将数据传给控制器并报告自身状态
	* 控制器将输入的数据存入数据寄存器，并将状态寄存器改为就绪
	* CPU 发现设备已就绪，将数据寄存器中的内容读入 CPU 的寄存器，再存入内存
	* 下一条指令
* CPU 干预的频率：
	* 很频繁
	* I/O 开始和结束时都需要 CPU 介入
	* 等待 I/O  完成时 CPU 需要轮询
* 数据的传输单位：字
* 数据的流向：
	* 输入：I/O 设备 -> CPU -> 内存
	* 输出：内存 -> CPU -> I/O 设备
* 优点：实现简单
* 缺点：CPU 和 I/O 设备只能串行工作，CPU 长期处于忙等状态，利用率低

中断驱动方式：
* 完成一次读 / 写操作的流程
	* CPU 发出指令后将等待 I/O 的进程阻塞
	* I/O 完成时控制器向 CPU 发出中断信号
	* CPU 检测到中断信号，保存当前进程的运行环境信息
		* CPU 在每个指令周期的末尾检查中断
	* CPU 从 I/O 控制器读一个字的数据传送到 CPU 寄存器再写入主存
	* CPU 恢复等待 I/O 的（或其他的）进程的运行环境
	* 下一条指令
* CPU 干预的频率：
	* 每次 I/O 操作开始和结束时 CPU 介入
	* 等待 I/O 完成时 CPU 切换到其他进程执行
* 数据传送的单位：字
* 数据的流向：
	* 输入：I/O 设备 -> CPU -> 内存
	* 输出：内存 -> CPU -> I/O 设备
* 优点：CPU 和 I/O 设备可以并行工作，CPU 利用率得到提升
* 缺点：频繁的中断处理会消耗较多的 CPU 时间

DMA（Direct Memory Access，直接存储器存取）方式：
* 数据的传送单位：块（连续的）
* 数据的流向：设备 -> 内存或内存 -> 设备（不需要经过 CPU）
* 完成一次读 / 写的过程：
	* CPU 指明此次进行的操作，并说明：
		* 读入多少数据
		* 数据存放在内存的什么位置
		* 数据在外部设备上的地址
	* 控制器根据 CPU 的要求完成读 / 写
	* 控制器向 CPU 发出中断信号
* DMA 控制器的组成：
	* DR（Data Register，数据寄存器）：暂存从设备到内存或内存到设备的数据
	* MAR（Memory Address Register，内存地址寄存器）：
		* 输入时表示数据放到内存中的什么地方
		* 输出时表示数据放在内存中的什么地方
	* DC（Data Counter，数据计数器）：表示剩余要读 / 写的字节数
	* CR（Command Register，命令 / 状态寄存器）：用于存放 CPU 的 I/O 命令或设备的状态信息
* DMA 每次读 / 写一个字，存入 DR，DR 满时一次性存入内存 / 磁盘
* CPU 干预的频率：仅在传送数据块的开始和结束时
* 优点：
	* 数据传输以块为单位
	* CPU 干预频率降低
	* CPU 和 I/O 设备的并行性提升
* 缺点：
	* CPU 每发出一条 I/O 指令，只能读 / 写连续的数据块
	* 读 / 写离散存储的数据块需要 CPU 发出多次 I/O 指令，多次中断处理=

通道控制方式：
* 通道：一种硬件，识别并执行一系列通道指令
* 完成一次读 / 写的过程：
	* CPU 向通道发送 I/O 指令，指明通道程序在内存中的位置，指明操作的 I/O 设备，随后切换到其他进程执行
	* 通道执行内存中的通道程序（其中指明了读 / 写的字节数、读 / 写数据存放位置等）
	* 通道执行完任务，向 CPU 发出中断，CPU 对中断进行处理
* 通道可以执行的指令很单一，与 CPU 共享内存
* CPU 干预的频率：只有在向通道发出指令和处理中断信号时需要 CPU 干预
* 读写单位：一组数据块
* 数据流向：I/O 设备 -> 内存 或 内存 -> I/O 设备
* 优点：CPU、通道、I/O 设备并行工作，资源利用率很高
* 缺点：实现复杂，需要专门硬件支持
