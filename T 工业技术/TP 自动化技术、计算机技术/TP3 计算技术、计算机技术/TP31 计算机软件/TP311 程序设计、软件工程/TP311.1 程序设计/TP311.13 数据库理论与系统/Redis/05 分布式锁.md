* 锁：
	* 临界区（Critical Section）：
		* 不能被打断的、必须一次性全部完成的一串代码
	* 竞态条件（Race Condition）：
		* 多个线程同时进入临界区导致结果错误
	* **作用**：
		* 保证同一时刻只有一个线程进入临界区
* 单机锁不适用于 Redis：
	* 多个 Java 实例各自的内存锁互相不可见
	* **解决方式**：
		* 将锁对象升级到进程外，由 Redis 管理
* **原理**：
	* Redis 为单线程，天然具有原子性
	* 获取锁：
		* `SETNX lock:user:100`
		* 若 key 不存在，则返回 `1`，表示已经获取到锁
		* 若 key 存在，则返回 `0`，表示已有进程占用锁
	* 释放锁：
		* `DEL lock:user:100`
* **注意事项**：
	* 必须设置过期时间兜底，避免死锁
	* 加锁和设置过期必须在同一条命令中，保持原子性
	* 使用 Redisson 自动续期，防止锁在业务结束前过期
	* 使用 UUID 作为锁的值，删除前检验，防止误删
* Java 实现：
	```java
Boolean locked = redisTemplate.opsForValue()
	.setIfAbsent("lock:answer:1", uuid, Duration.ofSeconds(30));
	```
