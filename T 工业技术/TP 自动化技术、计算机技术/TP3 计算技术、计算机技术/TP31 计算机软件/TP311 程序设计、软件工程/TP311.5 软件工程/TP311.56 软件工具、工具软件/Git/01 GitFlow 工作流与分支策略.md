# 01 GitFlow 工作流与分支策略

* 版本控制：
	* 记录文件的变化，并支持在任意时刻回滚历史状态
* 集中式与分布式：
	* 集中式：
		* 以 SVN 为代表
		* 版本库置于中央服务器
		* 需要联网
		* 历史记录只存放在服务器上
		* 服务器故障会导致全员无法工作
		* 难以实现功能分支
	* 分布式：
		* 以 Git 为代表
		* 每个人在本地都有完整的仓库副本，内含所有历史记录
		* 无需联网
		* 去中心化
		* 创建功能分支代价极低
* Git 三区模型：
	* 工作区：
		* 目前正在编辑的文件
	* 暂存区：
		* 准备提交的文件
		* 实现分批次提交
	* 本地仓库：
		* 本地的版本快照
	* 远程：
		* 团队共享
* Git 数据存储原理：
	* 每次提交时保存完整快照
	* 快照核心结构：
		* `blob`：
			* 文件内容
		* `tree`：
			* 目录结构
		* `commit`：
			* 快照的元数据
		* `tag`：
			* 标签
	* 每个快照使用 SHA-1 作为 ID，便于校验完整性
* `git add`：
	* 将工作区的修改存至暂存区
* `git commit`：
	* 将暂存区的更改提交到本地仓库
* `git push`：
	* 将本地仓库的更改推送到远程仓库
* 标准工作流程：
	* `git clone`：
		* 从远程拉取完整仓库，存为本地仓库
	* `git checkout -b feature/xxx`：
		* 创建功能分支
	* 修改代码
	* `git add. && git commit -m "提交消息"`：
		* 将修改完的代码存到暂存区，并提交到本地仓库
	* `git push`：
		* 将本地仓库推送到远程仓库
	* `git pull`：
		* 从远程仓库拉取最新的版本，包括其他团队成员的更新
* 分支：
	* **本质**：
		* 指向某次提交的指针
	* GitFlow 分支模型：
		* `main`：
			* 主线，随时可上线
		* `develop`：
			* 集成开发，隔离稳定版本与开发版本
			* 从 `main` 切出
		* `feature/*`：
			* 功能开发
			* 从 `develop` 切出
		* `release/*`：
			* 发版前准备
			* 从 `develop` 切出
		* `hotfix/*`：
			* 线上紧急修复
			* 从 `main` 切出
* `merge` 与冲突解决：
	* 冲突产生：
		* 同一文件的同一行被同时修改
	* 冲突标记：
      ```
		<<<<<<< HEAD
		本机内容
		=======
		别人的内容
        >>>>>>> feature/xxx
      ```
	* 解决步骤：
		* 编辑文件，保留想要的一方
		* 删除冲突标记
		* `git add`
		* `git commit`
* 常用命令：
	* `git status`：
		* 查看当前状态
	* `git diff`：
		* 查看未暂存的改动
	* `git diff --cached`：
		* 查看已暂存的改动
	* `git log --oneline --graph --all`：
		* 查看提交图
	* `git branch -a`：
		* 查看所有分支
	* `git switch -c feature/xxx`：
		* 新建分支并切换
	* `git commit --amend`：
		* 修改上一次提交
		* 只能在未 `push` 时使用
	* `git checkout -- 文件名`：
		* 丢弃改动，直接检出最新一次提交
	* `git ls-files`：
		* 列出所有被跟踪的文件
	* `git init`：
		* 初始化仓库
		* `--bare`：
			* 裸仓库
			* 只有历史，没有工作区
