* MCP（模型上下文协议）：
	* 实现了标准的 LLM 应用与工具之间的通信协议
	* 使任何编程语言可以参与到工具的实现中
	* 调用工具时不需要修改过多代码，可以单独适配
	* 采用 C/S 架构：
		* `MCP Server` 提供工具和资源，`MCP Client` 是智能体应用，通过 `stdio` 或 `http` 实现数据传输
		* 使用 JSON 格式传输数据
		* `stdio`：
			* 适用于服务端运行在本地的场景
			* 通过标准输入和输出通信完成相关操作
		* `HTTP`：
			* 服务器独立运行
			* 客户端通过 HTTP + SSE 通信，服务器完成任务操作，返回相关结果
	* 安装相关的依赖：
		* `langchain-mcp-adapters`：
			* 用于实现 MCP 客户端的功能
		* `fastmcp`：
			* 用于实现 Python 版本的 MCP 服务端
	* `fastmcp` 的工作：
		* 根据函数名和 `docstring` 生成工具的描述供 LLM 使用
		* 处理 MCP 协议通信过程中 JSON - RPC 的编解码
		* 将使用 `@mcp.tool` 装饰的函数对外提供 MCP 标准的方法供 LLM 使用
	* MCP 客户端使用异步方法访问
		* `async`：
			* 用于定义协程
		* `await`：
			* 用于暂停当前协程，等待异步操作完成
		* `asyncio.run()`：
			* 将协程置于事件循环中
	* 使用本地的 MCP 需要搭建相关运行环境
	* 使用远程 MCP 需要申请相关的 API 密钥
* 提示词工程：
	* 与 LLM 的交互本质是在规定的上下文空间（`messages`）中填充相关内容
	* **本质**：
		* 方法论工程，没有所谓正确的做法，只有更准确的做法
	* **目的**：
		* 使模型输出更加稳定、可靠
	* 完整提示词的组成部分：
		* 上下文：
			* 提供背景环境
		* 指令 / 任务：
			* 藐视需要模型做什么
			* 尽量使用动词描述清楚
		* 角色：
			* 设定相关身份，使模型输出更加符合对应身份的术语
		* 输出格式
		* 少样本提示：
			* 举例子，增强模型对格式要求或任务要求的理解
		* 思考链：
			* 引导模型如何推理
	* 提示词工程需要反复交流、优化，迭代出可靠的提示词内容，从而固定模型的输出格式
	* 现代 Agent 体系下的上下文工程、驾驭工程、循环工程本质是对提示词工程的优化和补充
* Skill：
	* **本质**：
		* 包含若干 markdown 的目录
		* 对任务细节描述的封装
	* 需要提前提供基础的上下文信息，告知智能体可以通过检索 Skill 文档，从而了解各项特定功能
	* `deepagents`：
		* 对 `langchain.agents` 的现代升级
		* `FilesystemBackend` 默认实现的工具：
			* `ls`：
				* 列出目录中的文件
				* 包含文件的元数据
			* `read_file`：
				* 按行读取文件内容
				* 支持图片等多模态文件
			* `write_file`：
				* 创建新文件或覆盖现有文件
			* `edit_file`：
				* 替换文件内容
			* `glob`：
				* 匹配查找特定文件
			* `grep`：
				* 检索文件内是否有相关的匹配内容
			* `execute`：
				* 执行 Shell 命令
		* `LocalShellBackend`：
			* 支持执行命令
		* 可以指定 Skill 的存放目录
