* 大语言模型工作原理：
	* 输入和输出内容都是**自然语言**，图片、文档等格式都是通过额外的模型或工具处理后实现的
	* **本质**：
		* 对下一个词的预测
	* **工作流程**：
		* 通过注意力机制解析计算输入
		* 输出一个 token，该 token 在概率上可能性相对大
		* 将输入与 token 拼接，得到新的输入
		* 重复上述操作，直到输出特定字符
	* 模型输出每一个 token 时都会使用一个词汇表计算 token 的出现概率，选择最高的作为输出
		* `Temperature` 参数能改变概率选择
	* 模型的大小很大程度上影响了模型自身对互联网上公开的文本和学习推理能力的高低
* token：
	* 有些字和词之间组合使用的概率很高，通常会合并作为单独的 token 处理
	* 一般一个汉字大约需要 1.5 ~ 2 个 token，英文单词大约 1 ~ 2 个 token
	* 主流分词算法：`BPE`
		* 从字符开始处开始分词，若字符之间存在高频关联，则将字符拼接成新的 token
		* 直到达到设定的词汇表上限（一般为 32000 ~ 100000）
* 上下文窗口：
	* 模型在生成内容时本质将先前生成的内容全部处理，得到后续内容
	* **定义**：
		* 模型一次性可以传入的最大 token 数
		* 包括输入和输出的全部内容
	* 很多模型至少支持了 128k 的 token 数量，部分模型可以支持接近 1M token
	* 由于注意力机制，越靠近窗口末尾的内容注意力越差，输出的内容越容易出现偏差
	* 若上下文窗口被填满，则可能会丢弃最早的信息
* 模型的消息角色：
	* `System`：
		* 系统指令
		* **作用**：
			* 设置 AI 的行为准则、规范等
		* 一般不展示
		* 优先级最高
	* `User`：
		* 用户指令
		* 用户发送的问题或指令
	* `Assistant`：
		* AI 回复的信息
		* 一般在多轮对话时需要回传
	* 与模型对话时，本质上构建了完整的历史消息数组，模型本身无状态
* `Temperature`：
	* **作用**：
		* 影响模型输出的随机性
		* 模型输出的 token 概率会除以 `Temperature` 值
	* 一般取值范围为 `[0, 2]`
	* **效果**：
		* `Temperature` 为 1 时，使用模型本身的输出概率
		* 越接近 0，则原始概率高的 token 概率会提升，得到稳定可靠的结果
		* 越接近 2，则会缩小 token 概率之间差别，得到创意结果
* LangChain：
	* 大模型开发框架
	* 可以实现聊天机器人、智能体
	* 提供了基于 Python 和 TypeScript 的 SDK
	* `langchain`：
		* 框架本体
	* `langchain-openai`：
		* 框架针对 OpenAI 兼容接口i的适配器
	* `python-dotenv`：
		* 用于加载 `.env` 配置的 Python 库
	* 提示词工程（Prompt Engineering）：
		* 通过对身份、提示词的处理，实现针对不同内容进行对应合理的输出
	* `stream`：
		* 流式传输
		* 持续从模型获得输出，而不是一次性获取完
		* 更符合用户心理
