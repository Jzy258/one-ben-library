* 路由（route）：
	* **作用**：
		* 在 SPA 中实现页面跳转效果
	* **原理**：
		* 将 URL 映射到 Vue 组件上，用户访问指定的 URL 时自动加载对应的组件，并卸载原组件
		* 映射存储在路由器（router）中
	* 需要安装 `vue-router` npm 包
	* ==component `Dashboard.vue`、`PageA.vue`、`PageB.vue`==
* `getCurrentInstance()`：
	* 获取当前组件的实例
* 路由器工作模式：
	* `history` 模式：
		* 基于 BOM 的 `history` 对象实现
		* URL 更美观，路径中不带有 `#`
		* 需要在 `nginx` 上处理路径问题，否则会出现 404 错误
		* 常用于面向消费者的系统
	* `hash` 模式：
		* 兼容性好
		* URL 不美观
		* SEO 优化较差
		* 常用于面向企业的系统
* 嵌套路由：
	* 遵循精确匹配原则
	* `RouterView` 的 `name` 属性可以绑定路由
	* 在父路由的 `children` 属性中配置子路由
	* 子路由的 `path` 不能以 `/` 开头
* 父组件向子组件传递数据：
	* query 方式：
		* 父组件在路由 URL 中拼接查询参数
			* 占位符使用 `${}`
		* 子组件使用 `useRoute()` 获取当前路由对象，通过路由对象的 `query` 获取传递的数据
			* 返回值为 JS 对象，可以使用解构语法
	* params 方式：
		* 在路由规则中配置 `path` 传参格式
			* 类似于 RESTful 风格，参数之间使用 `/` 分隔
			* 占位符使用 `:` 开头
			* `?` 结尾表示可选参数
		* 父组件在路由 URL 中拼接对应的参数
			* 占位符使用 `${}`
			* 或使用 `:to` 配置传入的 JS 对象
		* 子组件使用 `useRoute()` 获取当前路由对象，通过路由对象的 `params` 获取传递的参数
	* props + params 方式：
		* 在路由规则中添加配置 `props: true`
		* 父组件同 params 方式
		* 子组件使用 `defineProps()` 接收（与 props 相同）
	* props + qurey 方式：
		* 在路由规则中添加配置 `props(route) { return route.qurey; }`
		* 父组件同 query 方式
		* 子组件使用 `defineProps()` 接收
	* props 传递固定参数：
		* 在路由规则中配置 `props: { /* 固定数据 */ }`
* `RouterLink` 的导航模式：
	* `push`：【默认】
		* 将用户点击链接的记录采用 `push` 的方式压栈
	* `replace`：
		* 替换当前栈顶的记录
		* 在 `RouterLink` 标签上添加 `replace` 属性
		* 用于实现不支持某请求回退
* 编程式路由导航：
	* **流程**：
		* 通过 `userRouter()` 获取路由器
		* 通过路由器的 `push()` 完成路由跳转
	* **常见案例**：
		* 实现延迟跳转（通过 `setTimeout` 实现）
		* 实现按钮点击跳转
* 路由重定向：
	* 访问某个路由组件时，自动重定向到另一个路由组件
	* **实现**：
		* 在路由规则中配置 `{ path: '源', redirect: '目标' }`

补充：
* `history`：
	* **作用**：
		* 控制浏览器导航与路由
		* 允许 JS 与浏览器的会话历史记录交互
	* `history` 对象是 `window` 对象的一个只读属性，可以通过 `history` 或 `window.history` 访问
	* 主要属性和方法：
		* `length: number`：
			* 返回当前历史记录栈的页面总数
		* `back(): void`：
			* 加载历史记录的上一个页面
			* 相当于点击浏览器的“后退”按钮
		* `forward(): void`：
			* 加载历史记录中的下一个页面
			* 相当于点击浏览器的“前进”按钮
		* `go(offset: number): void`：
			* 加载历史记录中相对于当前页面的某个页面
			* 参数为负数表示后退，正数表示前进
			* `offset` 超出范围则静默失败，不抛出异常
			* `offset` 为 `0` 时刷新当前页面
	* HTML5 History API：
		* `pushState(state, title, url)`：
			* 向历史记录栈中添加新条目
			* 不刷新页面，但会改变浏览器地址栏的 URL
			* 新 URL 必须与当前页面同源（协议、域名、端口相同）
		* `replaceState(state, title, url)`：
			* 替换当前历史记录条目
			* 不刷新页面
			* 常用于更新当前页面状态
		* `popstate` 事件：
			* 每当激活的历史条目发生变化时触发
			* 调用 `pushState` 或 `replaceState` 不会触发
		* 参数说明：
			* `state`：
				* 历史记录条目携带的状态信息
				* JS 对象
				* `popState` 时会携带此对象
			* `title`：
				* 目前大多数浏览器都忽略该参数
				* 通常传入 `''` 或 `null`
			* `url`：
				* 历史记录条目的 URL
	* 典型应用场景：SPA 实现路由：
		* JS 阻止链接默认行为，通过 `fetch` 等 API 获取新内容并更新页面
		* 调用 `history.pushState()` 更新浏览器地址栏和历史记录
		* 监听 `popstate` 事件，根据 `state` 恢复对应的页面状态
	* 安全限制：
		* 只能将 URL 修改为同源地址，否则抛出 `SecurityError`
