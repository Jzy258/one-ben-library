# 03 Langchain实现复杂AI交互

* 支持视觉能力的 LLM：
	* 实现原理：
		* 将图片通过 Base64 算法转换成十六进制字符串发送给 LLM
	* 需要确保模型支持图片输入
* 多轮会话中的历史记录：
	* 每次调用模型都是全新的会话
	* 实现多轮对话：
		* 将历史消息（包括系统、用户和 AI 的对话内容）全部传给模型
	* **缺陷**：
		* 上下文窗口有容量限制
	* **解决方法**：
		* 滑动窗口：
			* 适用于对话
			* 维持 `msgs` 数组的最大容量，且永远保留开头的 `SystemMessage`
			* 若加入新内容后超出容量，则按需删除最早的内容
		* 压缩内容：
			* 适用于智能体
			* 对话内容超出容量后，单独调用一次大模型，总结先前的对话并替换
		* `langchain` 提供了专门的实现
* 模型传入参数：
	* `temperature`
	* `reasoning_effort`：
		* **作用**：
			* 指定思考推理强度
		* **可选值**：
			* `none`、`low`、`high`、`max`
* 多模型组合：
	* LangChain 支持多模型协作处理
	* 一般使用场景：
		* 大模型搭配小模型，节约成本
			* 大模型处理复杂问题
			* 小模型处理简单问题
		* 调用不同模型的能力，组合使用
			* 涉及图片的问题交给视觉模型处理
			* 其余交给推理能力更强的模型处理
		* 多个模型回答同一个问题，并总结分析，避免单一模型的幻觉误差
* Agent：
	* ReAct 模式：
		* Reasoning：
			* 分析现状，决定下一步要做什么
		* Acting：
			* 输出一个工具的调用指令
	* WorkFlow 模式：
		* 人工编写每一步的工作流程
	* 工具：
		* **本质**：
			* 通过 `@tool` 装饰器标记的函数
		* agent 会读取指定工具函数的 docstring，了解基本用法
		* 工具的定义顺序会影响 agent 的调用顺序
		* `docstring` 的书写规范：
			* 说明函数功能
			* 说明参数格式，给出示例
			* 提供基于自然语言的错误输出而非抛出异常
			* 返回值为自然语言
* Checkpointer：
	* **解决问题**：
		* agent 不能保存之前的消息记忆
	* `langgraph`：
		* `langchain` 的依赖
		* 用于实现更加底层的编排操作
* 中间件：
	* 控制智能体的规则引擎，用于在智能体调用 LLM 前后固定程序
	* `@dynamic_prompt`：
		* 动态提示词生成装饰器
	* 常用功能：
		* 动态提示词生成、日志、缓存、限流、安全审核等
