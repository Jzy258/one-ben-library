# 05 RAG检索增强生成

* 上下文工程：
	* 提示词是上下文的一部分
	* 使用较多的上下文容量后，模型的注意力会下降，导致内容劣化
	* 模型训练时的缺陷：
		* 训练使用的知识与现在发生的事存在信息差
		* 很多数据和信息是非公开的，且内容量超出模型的上下文空间
* RAG（Retrieval Augmented Generation，检索增强生成）：
	* 通过提供对一组数据（包括私有数据、近期数据等不属于 LLM 的训练数据）的推理访问来增强 LLM 的使用
	* RAG 模式：
		* Skill 引导检索：
			* 用户提问，智能体加载相关 Skill，调用工具检索事先提供的语料库，综合结果
		* 评分标准验证：
			* 用户提问，智能体检索证据并撰写草稿，用于评分的子智能体（通过 `RubricMiddleware` 配置）评估回答是否基于检索的原材料，智能体不断修订直到通过验证
		* 待办清单驱动调查：
			* 用户提问，智能体使用计划工具创建待办清单（包括文档页、搜索请求），逐个执行，汇总收集到的证据
		* 检索、卸载、委派：
			* 用户提问，智能体检索匹配的资料并写入文本系统，而非存入上下文，子智能体并行地读取、搜索并总结出单独的文件
			* 对于大文件，智能体会使用内置搜索工具分页，或从数据源生成表格、时间线或可视化图形
	* 检索、卸载、委派模式一般流程：
		* 建立索引：
			* 将语料库加载为向量并存储
		* 搜索：
			* 构建工具计算向量的相似度并将每个数据块写入文件系统
		* 分析：
			* 将文件委派给子智能体分析并返回总结
		* 汇总：
			* 使用主智能体得到最终回答
* 计算内容的相似度：
	* 计算距离（余弦距离）：
		* 使用嵌入模型（向量模型）将文本内容向量化
		* 计算向量的余弦距离，判断原文本的相关性和相似性
* 向量数据库：
	* 用于存储高维度向量
	* 将文本计算为向量后才能实现相似度计算
	* 常用向量数据库：
		* `chroma`、`pgvector` 等
	* Chroma：
		* 以单个文件的形式实现数据库存储
		* 可以通过相关的编程语言 SDK 访问
	* `langchain-chroma`：
		* LangChain 对 Chroma 的支持和实现
	* **一般流程**：
		* 导入文档
		* 使用嵌入模型将文档向量化并存储在向量数据库中
		* 使用 LLM 构建智能体
		* 用户发送消息
		* 嵌入模型根据消息筛选出合适信息来源并以系统消息的形式传给智能体
		* 智能体根据用户消息和系统消息回答
* 数据清洗：
	* 文本片段的质量直接影响到模型的最终表现
	* 对 doc、pdf、图片等格式需要专门的解析方式
	* 推荐的知识库文本格式为 markdown
	* 可以通过代码或工具（如 MinerU）对原始文档进行必要的预处理，预处理结果由人工审阅
* 子智能体：
	* 在特定场景下可以将任务委派给子智能体
		* 每个子智能体拥有独立的上下文、工具调用
		* 只将最终结果返回给主智能体
	* 设计要求：
		* 尽量让每一个子智能体单独做一件事
		* 设计好相关系统提示词，控制子智能体的工作边界，限制子智能体的输出内容
* 智能体的记忆与同步：
	* 记忆模式：
		* `Checkpointer`：
			* 短期记忆
		* `Store`：
			* 长期记忆
* Human-in-the-Loop：
	* **解决问题**：
		* 对 LLM 给予的权限越多，则对系统的潜在破坏的可能就越多
	* **解决方式**：
		* 通过加入人工审批引入安全边界限制
	* **实现**：
		* 在 `deepagents` 中配置 `interrupt_on` 以审批 Agent 对工具的调用
	* 审批模式：
		* `True`：
			* 中断操作，需要人类审批
		* `False`：
			* 不中断，Agent 可直接调用
		* `{"allowed_decisions": [...]}`：
			* 中断，并指定人类可用的审批类型
	* 审批类型：
		* `edit`：
			* Agent 接受用户提供的信息作为工具调用的参数
		* `reject`：
			* 直接拒绝 Agent 对工具的调用
		* `respond`：
			* Agent 不调用工具，但将用户提供的信息作为工具调用的结果
	* 可以使用 `ToolCallRequest` 为审批添加 `when` 条件，指定什么时候需要人类的介入，否则正常调用工具
